## Concerns found (not changed)

1. **`builder.ts` cannot detect declaration failures.** `@ohmyqt/oven`'s `Roll.tsc()` spawns `tsc` and ignores its exit status. Running the project's `tsc -p tsconfig.build.json` directly reports errors (`Cannot find module 'node:fs'`, `bun:test`) because `tsconfig.json` sets `typeRoots: ["node_module/@types"]` (missing `s`, so `@types/node`/`@types/bun` are not auto-included). Declarations are still emitted and the bundle is valid today, but a future type error would not fail `bun builder.ts`. Fixing this touches `tsconfig.json`, which was outside this task's allowed files.
2. **Build output depends on the `tsc` on `PATH`.** A plain `bun builder.ts` here picked up global TypeScript 7.0.2, while `node_modules/.bin/tsc` is 5.8.2. The final artifacts were rebuilt with the project compiler (`PATH="$PWD/node_modules/.bin:$PATH" bun builder.ts`) to match the README's supported matrix and `test/package-smoke.ts`, which prepends `node_modules/.bin`. Expect small generated-`types/` diffs (union ordering) if the builder is run without that prefix.
3. **`test/package-smoke.ts` expects a `log` runtime export** (its `expectedExports` list) that the current `src/index.ts`/`dist/index.js` do not export. That test lives in another worker's scope and will fail until the `log` export lands; it is unrelated to packaging metadata. Its `@ohmyqt/u` self-containment assertion now passes.
4. `types/helpers/mapped.d.ts` is a stale tracked artifact with no corresponding `src/helpers/mapped.ts`; any clean rebuild deletes it. The deletion is expected generated-output churn.
